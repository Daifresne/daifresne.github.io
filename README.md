# 折腾记录

个人博客的源文件。零依赖静态站：markdown 写文章，`node build.js` 生成 HTML，托管在 GitHub Pages。

## 目录结构

```
├─ site.json         ← 站点配置：站名、导航、分类标签、友链、单篇文章开关
├─ posts/            ← 文章（平时只往这里丢文件）
├─ pages/            ← 固定页面，如 about.md → /about.html
├─ assets/           ← 图片等静态资源，原样拷进 public/（没有就不建）
├─ build.js          ← 构建脚本（改长相/结构才动它）
├─ template.html     ← 页面骨架（改这里换结构）
├─ style.css         ← 全站样式（改这里换长相）
└─ public/           ← 生成结果，别手改
```

要改站点的什么东西，先看 `site.json`——站名、导航、分类、友链都在那儿，`build.js` 平时不用碰。

## 日常使用

```bash
# 写一篇新文章：在 posts/ 里建一个文件，文件名前面带上日期
#   posts/2026-09-20-新文章.md
# 然后把下面这个头貼上去，正文随便写
```

```markdown
---
title: 文章标题
date: 2026-09-20
tags: [MSPM0, 电赛]
summary: 一句话摘要，会显示在首页和 RSS 里。
---

正文从这里开始。
```

```bash
node build.js            # 生成到 public/
node build.js --serve    # 生成后起本地预览 http://localhost:8080
```

## 配置文件 site.json

站点里除了文章正文之外的东西都在这里。全部字段都可以不写，不写就是默认值。

```json
{
  "name": "站点名",
  "author": "作者",
  "url": "https://example.github.io",
  "description": "一句话站点介绍",

  "nav": ["首页", "分类", "友链", "关于", "RSS"],

  "tags": ["嵌入式", "单片机", "电赛"],

  "links": [
    { "name": "某人的博客", "url": "https://example.com", "desc": "介绍", "avatar": "" }
  ],

  "posts": {
    "2026-09-12-某篇还没写完的": { "draft": true },
    "2026-08-18-某篇重要的": { "pinned": true }
  }
}
```

### 导航 nav

写字符串，就按内置页面解析：`首页` `分类` `友链` `关于` `RSS`。
想加自己 `pages/` 里的页面，直接写文件名（`pages/日记.md` → 写 `"日记"`）。
要指向站外或者别的地方，用完整写法：

```json
"nav": ["首页", { "label": "我的 GitHub", "href": "https://github.com/Daifresne" }]
```

名字对不上任何页面时构建会提醒你，不会默默生出一个死链接。

### 分类 tags

**这个列表不决定「有哪些分类」**——分类是文章自己带出来的，写了就有。
它决定的是两件事：

1. **顺序**：列表里靠前的排在前面（登记过的按登记顺序，没登记的按文章数排在最后）
2. **统一叫法**：文章里用了没登记的标签会提醒你一句，免得同一个意思写成「单片机」「嵌入式」「嵌入式开发」三种

想给分类加句说明，写成对象：

```json
"tags": ["嵌入式", { "name": "电赛", "desc": "备赛和赛场上的事" }]
```

### 文章的开关 posts

按**文件名去掉 `.md`** 匹配，支持两个开关：

| 写什么 | 作用 |
|--------|------|
| `"draft": true` | 草稿。这次构建里当它不存在，首页、分类、RSS、sitemap 都不出现（文件留在那儿，改回 `false` 就发出去） |
| `"pinned": true` | 置顶。排在首页最前面，不受日期影响 |

名字写错、对不上任何文件时会提醒你，不用担心改了没生效。

### 友链 links

就是上面那个数组，增删改都在这儿。`avatar` 留空就自动显示名字的第一个字（圆形色块头像）。
`url` 填完不用管格式，构建时会取域名显示在卡片上；填得不对就原样显示出来。

## 写文章时怎么打标签

分类就是 front matter 里的 `tags`，一篇文章可以有多个：

```markdown
tags: [嵌入式, C, 电赛]
```

构建时会自动做三件事：首页顶部生成分类栏、每个分类生成一页 `/tags/xxx.html`、
`/tags.html` 汇总全部分类。

显示顺序和统一叫法由 `site.json` 的 `tags` 管（见上面）。建议固定一套用词，
同一个概念别一会儿写「嵌入式」一会儿写「嵌入式开发」：

| 大类 | 建议写法 |
|------|----------|
| 硬件/嵌入式 | 嵌入式、单片机、电路 |
| 编程语言 | C、C++、C#、Python、Java |
| 方向 | CTF、算法、前端、工具 |
| 杂记 | 随笔、踩坑、折腾 |

## 支持的 markdown 语法

标题、段落、**粗体**、*斜体*、~~删除线~~、`行内代码`、围栏代码块、链接、图片、
无序/有序列表（缩进两级嵌套）、任务清单 `- [ ]`、引用、表格、分隔线。

以 `<` 开头的行会按原始 HTML 输出，所以可以直接贴 `<iframe>` 嵌别的东西。

## 部署

推到 GitHub 后由 Actions 自动构建并发布（见 `.github/workflows/deploy.yml`）。
仓库第一次建好后，去 **Settings → Pages → Source** 选 **GitHub Actions**，之后每次 push 都会自动更新。

站点信息（名字、作者、网址、描述）改 `site.json`，改完 push 就行，`build.js` 不用动。

## 备注

`posts/` 里现有三篇是示例，看懂格式后删掉换成自己的。
配置写错不会把构建搞挂：认不出的字段、对不上的文件名、没登记的标签都只是打印一句提醒，
站点照样建出来，你可以照着提醒回去改。
